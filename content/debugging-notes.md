隔一周再看一段调试记录，最难想起来的往往是当时改过什么。终端里可能还留着错误栈，但复现用的是哪个版本、哪个输入，已经要重新猜一遍。

## 把复现命令放在第一行

假设一个 CSV 导入脚本只在空字段出现时失败。我会先保存最小输入，再记录工作目录和完整命令：

```bash
python import_rows.py fixtures/one-empty-field.csv --dry-run
```

这条命令旁边只放两项结果：

- **预期**：接受两行记录，把空字段保留为空字符串。
- **实际**：导入在第二行报错，提示尝试将空字符串转为整数。

## 每次实验只改一个条件

复制输入文件，把第二行的空字段换成 `0`，再跑同一个命令。如果这次通过，笔记里就能明确写下哪一个改动影响了结果。至于空值应该保留还是按规则填充，要回到字段约定里确认。

修好后，把最小输入留作回归用例。下次遇到类似问题时，可以从命令开始重放整个过程。
